개인정보처리방침

회원가입·소셜 로그인, 결제, 광고 없이 이용하는 보카월드 테스트 버전의 개인정보 처리방침 초안입니다.

초안 작성일: 2026년 11월 9일 · 시행일: 배포 일정 확정 후 안내

이용약관처리하는 정보삭제·문의

1. 적용 범위와 운영자

이 방침은 보카월드 앱과 공식 안내 홈페이지에 적용됩니다. 앱 마켓과 운영체제의 별도 데이터 처리는 각 제공자의 정책에 따릅니다.

2. 처리하는 정보와 목적

테스트 버전에는 이메일·비밀번호 회원가입, 소셜 로그인, 유료 결제 및 광고 기능을 제공하지 않는 것을 기준으로 합니다. 이러한 기능을 위해 이름, 전화번호, 결제수단 정보를 요구하지 않습니다. 고객지원 이메일을 보내면 회신 주소와 문의 내용은 처리됩니다.

현재 기기 내 기록과 서버 도입 예정 항목
구분정보목적·상태
기기 내 게임 기록게임별·난이도별 최고 점수, 틀린 단어 ID와 횟수, 출석·미션 기록, 보유 재화 및 소리 설정학습 복습, 진행 상태와 환경설정 유지. 현재 앱 저장 코드에서 확인한 항목이며, 틀린 단어 기록의 서버 수집은 이번 범위에 포함하지 않습니다.
게스트 식별·인증
도입 예정		게스트 사용자 ID, 인증 처리에 필요한 토큰같은 이용자의 기록 구분 및 접근 권한 확인. 이름을 몰라도 지속적으로 연결되는 ID는 개인정보에 해당할 수 있습니다. 구체적인 인증 방식과 인증 서비스의 처리 정보는 도입 시 확정합니다.
서버 랭킹
도입 예정		게스트 사용자 ID, 공개용 별명, 게임 종류·난이도, 점수, 기록 시각, 게임 실행 ID, 앱·점수 규칙 버전순위 산정, 중복 기록 방지 및 기록 검증. 실제로 사용하는 항목만 서버에 저장합니다.
하트
서버 관리 여부 미정		하트 잔량, 충전 기준 시각, 필요한 소모·지급 내역서버에서 하트 소모·충전을 관리하기로 결정한 경우에만 처리합니다.
크리스탈기기 내 보유 수량현재 서버 지급·구매 기능을 전제로 하지 않습니다. 서버 저장은 관련 기능 도입 여부를 정한 뒤 별도로 안내합니다.
고객지원발신 이메일 주소, 문의 내용, 이용자가 첨부한 자료, 필요한 경우 기록 식별 정보문의 답변과 오류 확인, 개인정보 관련 요청 처리. 비밀번호·인증 토큰·주민등록번호 등 불필요한 정보는 보내지 마세요.
접속·진단 정보
설정 확인 필요		서버·호스팅 접속 기록, 분석 이벤트, 오류·기기 정보 등 실제 활성화된 서비스의 처리 항목보안과 장애 대응 등. 현재 프로젝트에 Firebase Analytics·Crashlytics SDK가 포함되어 있어 배포 빌드의 자동 수집 여부와 구체적인 항목·목적을 확정해야 합니다.

서버 기능은 해당 기능 이용 시 앱과 서버의 통신을 통해 정보를 처리합니다. 지원 문의는 이용자가 이메일을 보낼 때 접수합니다. 기기 내 기록은 운영체제의 백업 설정에 따라 백업될 수 있으므로, 앱 개발자의 서버 수집과 구분됩니다.

기능별 처리의 법적 근거와 동의 필요 여부는 최종 데이터 흐름에 맞춰 확정합니다. 동의가 필요한 경우 수집 전에 항목·목적·보유 기간·거부 시 영향을 별도로 안내하고 동의를 받습니다.

3. 랭킹에 공개되는 정보

서버 랭킹을 도입하면 다른 이용자에게 공개용 별명, 순위, 게임 종류·난이도, 점수가 표시되도록 설계합니다. 내부 사용자 ID, 인증 토큰, 하트·크리스탈 잔량과 개인별 틀린 단어 기록은 랭킹 공개 항목에 포함하지 않습니다. 공개 범위는 랭킹 참여 전에 안내합니다.

4. 보유 기간과 파기

  • 기기 내 기록: 앱 데이터 삭제 등으로 제거할 수 있습니다. 앱 삭제 후 운영체제 백업에서 복원되는 데이터는 해당 백업 설정을 함께 확인해야 합니다.
  • 서버의 게스트·랭킹·하트 정보: 보관 기간과 테스트 종료 후 삭제 시점을 확정한 뒤 서버 수집을 시작합니다. 이용 중인 앱을 삭제하는 것만으로 서버 기록이 삭제되지는 않습니다.
  • 고객지원·접속·진단 정보: 문의 처리 목적과 보안상 필요에 맞는 항목별 보관 기간, 외부 서비스의 보유·백업 기간을 확정해야 합니다.

처리 목적 달성, 보유 기간 종료 또는 적법한 삭제 요청에 따라 더 이상 필요하지 않은 정보는 지체 없이 파기하는 것을 원칙으로 합니다. 법령에 따라 보존해야 하는 경우에는 해당 근거·항목·기간을 명시하고 별도로 관리합니다. 전자 파일은 복구가 어렵도록 삭제하며, 백업에 남는 정보의 삭제 주기도 최종 방침에 명시합니다.

5. 제3자 제공, 처리 위탁과 국외 이전

랭킹 공개와 서버 운영을 위한 처리 위탁은 구분하여 안내합니다. 인증·데이터베이스·호스팅·메일·분석·오류 수집 서비스를 사용하면 실제 수탁자, 처리 업무, 보관 기간 등을 확인하여 고지합니다. 현재 설치된 Firebase SDK만으로 실제 처리 업체의 계약 주체나 저장 국가를 확정하지 않습니다.

국외 이전이 발생하는 경우 이전 항목, 국가, 시기·방법, 이전받는 자와 연락처, 이용 목적·보유 기간, 이전의 법적 근거 및 해당되는 거부 방법·효과를 확정하여 안내합니다. 데이터베이스 리전만으로 인증·분석 등 모든 서비스의 처리 국가가 같다고 보지 않습니다.

6. 열람·정정·삭제 등 권리와 문의

이용자 또는 법정대리인은 관계 법령에 따라 개인정보의 열람, 정정·삭제, 처리 정지, 동의 철회를 요청할 수 있습니다. 빌드 시 지원 이메일 표시로 요청 내용과 회신에 필요한 정보를 보내 주세요. 요청 처리에 필요한 범위에서 본인 또는 대리인 여부를 확인합니다.

게스트 기록의 경우 공개된 ID만으로 소유자를 확정할 수 없으므로, 해당 앱에서의 인증 등 안전한 확인 절차가 필요합니다. 게스트 인증 정보가 사라지면 기록의 소유 확인과 복구가 어려울 수 있습니다. 서버 기록을 도입하기 전에 실제 삭제 요청 절차와 처리 방법을 함께 마련합니다.

7. 아동의 개인정보

테스트 대상 연령은 확정 전입니다. 만 14세 미만 아동의 개인정보 처리에 법정대리인 동의가 필요한 경우, 동의 및 확인 절차를 마련한 뒤 처리합니다. 아동을 대상으로 제공할 경우 앱 마켓의 아동·가족 정책과 연령에 맞는 설명도 함께 적용합니다.

8. 안전한 처리와 자동 수집 설정

서버 도입 시 암호화된 통신, 인증 토큰 검증, 접근 권한 제한, 기록 검증 및 삭제 절차를 적용하고 실제 조치 내용을 최종 방침에 반영합니다. 현재 홈페이지에는 자체 로그인·문의 입력 폼이나 별도로 추가한 광고·분석 스크립트가 없습니다. 다만 호스팅·메일 서비스의 처리와 앱 SDK의 자동 수집 여부는 별도로 확인해야 합니다.

9. 방침 변경

이 방침을 변경하면 변경 내용과 시행일을 홈페이지와 필요한 앱 내 안내를 통해 알립니다. 향후 계정 로그인, 결제, 광고 또는 오답 기록의 서버 동기화를 도입할 때에는 실제 처리 내용에 맞춰 방침과 앱 마켓의 데이터 공개 항목을 먼저 갱신하고, 필요한 경우 별도 동의를 받습니다.
